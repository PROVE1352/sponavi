# 스포내비 PRD (Product Requirements Document) v1

> 작성 2026-07-20. 위상: `PLAN.md`(왜) → `ARCHITECTURE.md`(어떻게) → **PRD(정확히 무엇을)**.
> 모든 FR에 인수조건(AC)이 붙는다 — AC는 테스트로 옮길 수 있는 문장만 쓴다.
> 2심 판결 보완명령은 ★로 표기된 요구사항으로 승격됨(협상 불가).

## 0. 제품 원칙 (전 기능 공통 — 위반하면 그 기능은 미완)

- **P-1 정직성**: 모르는 것은 모른다고, 근사값은 근사라고 표시한다. 거짓 정밀도 금지.
- **P-2 레인 분리**: 자격·위치·가격 = 결정론(규칙+SQL). AI는 체력처방 조언만. AI 출력이 자격·시설·가격을 언급하면 폐기.
- **P-3 비저장**: 사용자 입력(소득·장애 등)은 요청-응답 한정. 서버 로그에 바디 미기록. 저장되는 것은 익명 캐시 키(해시)뿐.
- **P-4 예상 자격**: "자격"은 항상 "예상 자격"으로 표기, 공식 신청처 링크+출처·확인일 각주 동반.
- **P-5 접근성**: 장애인이 1차 사용자다. §7 접근성 요구는 기능 요구와 동급이다.

## 2. 기능 요구사항 — 코어 플로우

### FR-01 입력 위저드
사용자가 나이·성별·시군구·소득계층(4택 자가선언)·장애(유무+유형 8택)를 입력한다.
- AC1: 필수값 미입력 시 제출 불가 + 어떤 값이 빠졌는지 필드 옆 안내.
- AC2: 시군구는 검색 가능한 셀렉트(전국, sigungu 테이블 278개 — 서울만 아님).
- AC3: 소득계층 선택지에 "잘 모르겠어요" 포함 → 선택 시 결과에 "기초·차상위 확인 방법" 안내 블록 추가(복지로/주민센터 링크). *(오해 사각지대 대응: 자기 계층을 모르는 사용자가 다수)*
- AC4: 입력 어디에도 이름·연락처·주민번호 요구 없음(P-3).

### FR-02 자격 판정 카드
제도별 "예상 자격 ✓/✗" + 조건별 사유 + (✓시) 신청 방법·서류·기간·공식 링크.
- AC1: 사유는 조건 단위로 표시("연령 5~18세 — 27세는 범위 밖")— reasons 배열 그대로.
- AC2: 카드 하단에 출처 URL + 확인일("2026-07-20 공식 확인"). `verified:false`면 "공식 확인 필요" 배지.
- AC3: **장애 있음 + dvoucher 대상일 때 "소득과 무관하게 대상입니다" 문구를 카드 최상단 강조** (오해 격파 훅).
- AC4: ✗여도 카드가 사라지지 않는다 — "왜 안 되는지"가 정보다.

### FR-03 경로 시각화
개인→제도(✓/✗)→(대안)→시설의 스텝 다이어그램.
- AC1: path 배열의 엣지 라벨·결과색(✓초록/✗빨강, 색+아이콘+텍스트 삼중)이 렌더.
- AC2: `curated:"검증 대기"` 엣지에 "전문가 큐레이션" 뱃지.
- AC3: 모바일 390px에서 가로 스크롤 없이 표시(세로 접힘 허용).

### FR-04 근처 자원 (지도+리스트) — ★좌표 정직성 (2심 판사2 처방, 협상 불가)
- ★AC1: **좌표가 구 중심 폴백인 시설(voucher/dvoucher)은 마커·리스트에 "위치 근사(구 중심)" 배지**를 단다.
- ★AC2: **"반경 N km" 문구는 실좌표 보유(public) 풀에만 사용**한다. 이용권 시설은 **"성북구 가맹 N곳"**(구 단위 카운트)으로 표기한다. dist_km는 근사 시설에 표시하지 않는다.
- AC3: 마커 색: 이용권=파랑, 공공/대안=초록, 장애인=보라 (범례 상시).
- AC4: 리스트 항목: 시설명·종목·(실좌표면 거리)·수강료·**자부담 계산**(`max(0, 수강료−지원금)`, 지원금 상수는 rules.json 값)·장애인지원 태그(1/0/미상 3상태).
- AC5: 지도는 OSM 타일 + attribution. 마커 20개 초과 시 상위 20 + "더보기".

### FR-05 공급공백 배너 + 커버리지 (정직 신호, 상시)
- AC1: 해당 소스 시설 카운트 0이면 결과 최상단에 경고 배너: "이 지역엔 ○○ 시설이 없습니다 + 최근접 시설명·거리(실좌표일 때만 km, 아니면 '△△구')".
- AC2: 커버리지 존재 구: "이 구 {계층} {target}명 중 {recipient}명 수령({rate}%)" 한 줄. **없는 구는 "수급 통계 데이터 없음"** — null을 0이나 추정으로 채우지 않는다(P-1).
- AC3: 배너는 닫을 수 있으나 기본 표시.

### FR-06 데모 페르소나 바
- AC1: P1~P4 버튼, 클릭 1회로 해당 결과 화면 완성(입력 프리필+자동 제출).
- AC2: 각 버튼에 기대 결과 한 줄(라벨) 표시.

## 3. 기능 요구사항 — AI 체력처방 (M1)

### FR-07 측정 입력 폼 (동적)
- AC1: `measurement_item` 카탈로그에서 **사용자 연령군 해당 항목만** 렌더(유아·청소년·성인·어르신 SET 매칭), 9개 체력요인 그룹핑.
- AC2: 전 항목 선택 입력(null 허용) — 최소 1개 입력 시 제출 가능.
- AC3: 각 항목에 단위·측정법 힌트(예: "악력(kg) — 양손 중 높은 값").
- AC4: "국민체력100 인증센터에서 무료 측정 가능" 안내 + 센터 찾기 링크.

### FR-08 AI 처방 호출
- AC1: 프로바이더 순서 = env `SPONAVI_LLM`(claude|gemini|off). off 또는 실패 시 룰 폴백.
- AC2: LLM 출력은 pydantic 스키마 검증(약점[]·우선순위[]·처방[{운동,요인,강도,빈도}]·주의). 검증 실패 → 1회 재시도 → 폴백.
- AC3: **응답에 `provider: claude|gemini|rules` 필드** — UI가 "AI 보조 처방" vs "기본 규칙 처방" 구분 표기(P-1).
- AC4: 캐시: (연령군·성별·항목값 반올림) 해시 적중 시 재호출 없음.
- AC5: 처방 화면에 고지 문구 고정: "운동 참고 정보이며 의료 조언이 아닙니다. 통증·질환 시 전문가와 상담하세요."
- AC6: LLM 프롬프트에 시설·가격·자격 언급 금지 지시 포함, 응답에 해당 내용이 있어도 서버가 무시(P-2).

### FR-09 처방→강좌 연결 (결정론 복귀)
- AC1: 처방 운동명 → 종목 사전 정규화 → 사용자 시군구의 시설·강좌 필터("이 운동 되는 근처 강좌 N곳").
- AC2: 매칭 0곳이면 숨기지 말고 "이 운동을 다루는 등록 강좌가 이 지역에 없습니다" + 공공시설 일반 대안(P-1).
- AC3: 국민체력100 동영상 링크 최소 1개(약점 요인 매칭, videos 데이터).

## 5. 데이터 요구사항

- DR-1: DB 갱신 월 1회(`bulk_fetch → build_db`), 갱신일을 UI 푸터에 표기("데이터 기준 2026-07-20").
- DR-2: 자격 수치(연령·지원금)는 rules.json에서만 — 하드코딩 금지. 출처 URL·checked 필수.

## 7. 접근성 요구 (장애인이 1차 사용자 — 기능과 동급)

- A11Y-1: 전 인터랙션 키보드 완주 가능(포커스 표시 포함). 지도의 정보는 리스트로도 동일 접근 가능(지도 없이 완결).
- A11Y-2: 스크린리더: 폼 라벨·에러·배너에 적절한 role/aria(경고 배너 role=alert), 이미지 마커에 대체텍스트.
- A11Y-3: 상태는 색+아이콘+텍스트 삼중(색맹 안전). 대비 WCAG AA.
- A11Y-4: 폰트 200% 확대 시 레이아웃 파손 없음.
- A11Y-5: 장애유형 선택지는 존중 표현(법정 유형 명칭 사용), 불필요한 세부 요구 금지.
- AC(공통): Playwright + axe-core 자동 점검을 e2e에 포함, 치명(critical) 위반 0.
