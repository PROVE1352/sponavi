# 체력 지식그래프 & GraphRAG 설계 v1

> 작성 2026-07-21. 3대 에이전트 실사(제도·API실데이터·처방근거) 종합.
> 원칙 유지: **판정은 결정론(공식 컷오프), 그래프는 근거의 보관소, LLM은 문장 렌더링만.**
> 자격 레인의 GraphRAG 비채택(ARCHITECTURE §10)은 그대로 — **채택 범위는 처방 레인 한정.**

## 0. 왜 그래프인가 (한 줄)

처방 질의는 본질이 멀티홉이다: *"어르신 + 하지근력 약점 + 지체장애 → 낙상예방 운동 → 저충격 종목 → 수중리프트 있는 근처 시설"* — 이 경로를 평면 룰(fitness_map 8행)로는 못 담고, 매 홉에 **출처 있는 엣지**가 있어야 정직성 원칙이 지켜진다.

## 2. 그래프 스키마

### 노드 (7종)
```
Factor        체력요인 9: 심폐지구력·근력·근지구력·유연성·민첩성·순발력·협응력·평형성·신체조성
              (+어르신 변형: 근기능상지·근기능하지 — Factor의 age_variant 속성)
Exercise      운동 (pres_note+영상에서 채굴, canonical name) 예: 걷기, 버피 테스트, 앉았다 일어서기
Sport         종목 34 (courses.sport 정규값) 예: 태권도, 헬스, 수영, 클라이밍
AgeGroup      유아(4-6)·유소년(11-12)·청소년(13-18)·성인(19-64)·어르신(65+)  ※7-10 공백 명시
DisabilityType 지체·시각·청각/언어·지적/자폐·뇌병변·기타 (dvoucher 8분류와 정렬)
Goal          목적: 낙상예방·요통예방·체중감량·재활 (영상 trng_aim_nm에서)
Context       제약: 장소(실내/헬스장/집)·도구(맨몸/밴드/짐볼)·강도수준(초/중/상급)
```

### 엣지 (rel + provenance 필수)
```
improves   (Exercise|Sport) → Factor   "이 운동이 이 요인을 기른다"
targets    Exercise → Goal             낙상예방 등 (영상 목적축)
suits      (Exercise|Sport) → AgeGroup 연령 적합 (영상 aggrp + 지침)
caution    (Exercise|Sport) → (DisabilityType|Condition)  주의·금기 (국립재활원 등)
accessible Sport → DisabilityType      dvoucher 장애지원유형 실데이터 (E76)
needs      Exercise → Context          장소·도구·수준
member_of  Exercise → Sport            운동↔종목 소속 (수영 exercise ↔ 수영 sport)
offered_as Sport → (courses SQL)       그래프 밖 리프 — 실행 시점 조인
```

### 엣지 provenance (정직성의 핵)
| 등급 | source 값 | 뜻 | UI 배지 |
|---|---|---|---|
| **S** | `kspo_standard` | KSPO 건강체력기준 페이지 명시 | "공단 공식 기준" |
| **P** | `kspo_presnote` | 처방 코퍼스 채굴 (빈도 동봉) | "공단 처방 실적 N건" |
| **V** | `kspo_video` | 영상 카탈로그 분류축 | "공단 콘텐츠 분류" |
| **A** | `guideline` | 복지부 2023·질병청·WHO·ACSM | "정부·국제 지침" |
| **B** | `curated` | 체대 큐레이션 (status: pending/verified) — §3 매트릭스 `trains` + §3.5 목적→요인 `improves` | "전문가 큐레이션(검증 중)" |

모든 엣지: `{src, dst, rel, source, evidence(원문/URL/빈도), weight, curated_status}`. **출처 없는 엣지는 존재할 수 없다** — rules.json 원칙의 그래프 확장.

## 3.5 목적(Goal) → 요인 시드 & 신체조성 연결 (2026-08-22 추가)

### 왜 필요했나
영상 카탈로그의 목적(Goal) 16개에 `targets` 엣지 462개가 붙어 있는데도 Goal 이 Factor 로
이어지지 않아 §5 리트리벌의 **멀티홉(운동 →targets→ 목적 →improves→ 요인)이 사실상 죽어
있었다**(Goal→Factor 엣지가 낙상예방 2개뿐). 또 `measurement_item` 에 신체조성 항목
(bmi·whtr·body_fat)이 있어 약점으로 판정될 수 있는데 KSPO 공식 매핑에 신체조성 행이 없어
`recommend_for_weakness(["신체조성"])` 가 **빈 배열**이었다(고아 요인).

### 티어 정책 (정직성 — 연결 수보다 근거가 우선)
| 티어 | source | 채택 조건 | weight / status |
|---|---|---|---|
| **A** | `guideline` | 복지부 한국인 신체활동 지침 2023 · WHO 2020 · ACSM · 질병관리청으로 "이 목적에는 이 요인의 운동"을 **구체 문장으로 쓸 수 있을 때만** | 0.8 / — |
| **B** | `curated` | 그 외 전부 — ① 목적 분류명에 요인이 명시(이름 근거) ② 공단 영상 요인 태그 실측 분포(루틴 구성 근거) | 0.5 / `pending` |

- 카탈로그 실측 채택 기준: 해당 목적 영상 중 그 요인 태그 **점유율 20% 이상**
  (예: 직장인동료짝운동의 `근력/근지구력` 11/92=12% → 제외). 수치는 2026-07-21 적재본 실측.
- **명시적 비매핑**: 질병예방 목적(고혈압·당뇨·우울증)에 유산소 지침은 존재하지만 해당 루틴
  영상에 심폐지구력 태그가 하나도 없어 **심폐지구력으로는 잇지 않는다**. 지침 수치는 처방의
  FITT 슬롯(`ai.py`)에서 별도 인용된다.
- **경로 등급 = 최약 링크**: 멀티홉 후보의 provenance 는 두 홉 중 약한 쪽을 쓴다
  (`graph._weakest`). 목적→요인이 A급이어도 운동→목적이 V급이면 그 운동의 근거는 V급이다.
  경로는 `via_goal`·`via_goal_source` 로 남긴다.

## 5. 리트리벌 & 생성 플로우 (GraphRAG 본체)

```
[결정론] 입력(연령·성별·측정값) ── fitness_norm 컷 비교 ──▶ 약점요인 + 참고등급("공식 인증 아님" 라벨)
                                                        └ 291만 실데이터 분위수로 "상위 N%" 부가 표시
[그래프 탐색 — 결정론] (약점요인, 연령군, 장애유형?, 목적?, 장소제약?)
   1-hop: Factor ←improves─ Exercise/Sport
   필터:  suits(연령군) ∧ ¬caution(장애·상태) ∧ needs(장소·도구 가능한 것) ∧ accessible(장애 시)
   랭킹:  provenance(S>P>A>V>B) × 코퍼스 빈도 × ★근처 강좌 가용성(offered_as 조인 결과 수)
   출력:  서브그래프 = 운동 후보 + 종목 후보 + 영상 URL + 각 홉의 근거(출처·원문)
[LLM 렌더 — 생성은 여기만] 입력 슬롯 = 서브그래프 + FITT 수치사전 + 처방사 톤 가이드
   금지: 슬롯 밖 수치·운동명·의학 조언 생성 (스키마 검증 실패 시 1회 재시도 → 룰 폴백)
   톤(공단 처방사 실화법): 약점 지목 → 목표 수치 → 구체 운동·도구 → 생활 팁
[후처리 — 결정론] 종목 → 근처 강좌 SQL (+장애 시 dvoucher 편의시설 필터) → "이 처방 되는 강좌 N개"
```

**차별화 핵심 = 공급 인지 처방(supply-aware)**: 랭킹에 강좌 가용성이 들어가므로 "수영이 최선이지만 반경 내 수영 강좌 0개 → 차선 에어로빅(근거 제시)"이 가능. 처방 레인이 공급공백 신호기와 한 몸이 된다. 데모 동선: 인천서구 어르신 = 낙상예방 처방 + "근처 가맹 0곳" 정직 신호 + 비대면 강좌 대안(E75).

**v1에 임베딩 불필요**: 운동명 명명체계가 pres_note↔영상 간 동일함을 실측(퍼지 아닌 정규화 조인으로 대부분 해소). 임베딩은 미매칭 잔여 운동명 정규화(오프라인 1회)에만 — "GraphRAG"의 R은 벡터가 아니라 **그래프 탐색**이다.
