# 스포내비 (SpoNavi) — MVP 계약서 v1

> 2026 KSPO 공공데이터 활용 경진대회 "서비스(앱·웹) 개발 부문" 출품용 MVP.
> 취약계층·낀 계층·장애인이 **조건만 입력**하면 자격을 판정하고, 미달이면 **대체경로**로
> 무료/저가 스포츠 자원에 연결하는 당사자용 웹 서비스. 백엔드는 자격·대체경로 지식그래프.

## 0. 판결 제약 (아이디어 법정 1심 PIVOT — 반드시 지킬 것)

1. **공급공백 정직 신호**: 반경 내 대안 0건이면 추천하는 척하지 말고 "이 지역은 이용 가능한
   시설이 없습니다 + 가장 가까운 곳 X(Y km) + 시군구 커버리지 통계"를 노출한다. (검사 혐의1 대응)
2. **near-poor를 간판에 걸지 않는다**: 낀 계층은 4개 케이스 중 하나다. 랜딩 카피는 중립
   ("스포츠 복지 내비게이터"). 간판 프레이밍(장애인 앵커 vs 스포츠 온램프)은 인터뷰 후 결정. (혐의2)
3. **대체경로 = 전문가 큐레이션 규칙**: "AI 추론"이라 부르지 않는다. alt_edges는 사람이 검증하는
   규칙 테이블이고, UI에도 "전문가 검증" 프레이밍. 시드 엣지에는 `curated: "검증 대기"` 플래그. (판사2)
4. **멀티홉 경로를 3분에 체감**: 결과 화면에 "왜 이게 나왔나" 경로 시각화(개인→제도✗→대안→시설)
   필수. 데모 페르소나 4개 원클릭. (혐의3)
5. **자격 규칙 날조 금지**: 이용권/장애인이용권의 자격(연령·소득·장애)은 공식 사이트
   (svoucher.kspo.or.kr / dvoucher.kspo.or.kr)에서 **검증 후** rules.json에 출처 URL·확인일과 함께
   인코딩한다. 확인 못 한 항목은 `"verified": false`로 남기고 UI에 "공식 확인 필요" 배지.

## 1. 범위

**한다(MVP)**: ① 자가입력 → 자격판정+신청안내 ② 자격 미달 → 대체경로(공공체육시설·무료/저가)
③ (선택) 체력측정값 → 약점 → 운동 → 되는 시설 필터 ④ 공급공백 신호+커버리지 통계 ⑤ 데모 4페르소나.
**안 한다**: 로그인/개인정보 저장(입력은 세션 한정), B2G 대시보드, 실시간 예측, 예약/결제,
개인 추적. 파일럿 지역 = **서울 25개 구** (fixtures도 서울).

## 2. 데이터 전략 — fixtures 우선, 키 주입형 ETL

지금 data.go.kr 인증키가 없다. 따라서:
- 앱은 `data/fixtures/*.json`만으로 완전 동작(데모 모드)해야 한다.
- `scripts/fetch_data.py`는 `DATA_GO_KR_KEY` env로 실데이터를 받아 같은 스키마의 JSON을 생성
  (키 없으면 명확한 안내 후 종료). 소스:
  - 이용권 등록시설 15107783 / 등록강좌 15107784 (비장애, 자동승인, **좌표 없음**)
  - 장애인 등록시설 15107874 / 등록강좌 15117341 (자동승인, 좌표 없음)
  - 전국 공공체육시설 15113986 (**faci_lat/faci_lot 좌표 있음**, 운영상태)
  - 운동처방 동영상 15108846 (연령대·운동명·부위 필터)
- 좌표 없는 시설 지오코딩: `KAKAO_REST_KEY` 있으면 카카오 주소검색, 없으면 시군구 중심좌표 폴백
  (`data/sigungu_centroids.json`, 서울 25구 하드코딩 시드 — 서버 에이전트가 작성).
- 커버리지 통계: `data/fixtures/coverage_seoul_2025.json` (실측 미리보기 행 — 이미 확보됨).

## 3. 온톨로지 (rules.json — 서버가 로드하는 단일 진실)

```jsonc
{
  "programs": [            // 제도 노드
    {
      "id": "svoucher",
      "name": "스포츠강좌이용권",
      "eligibility": {     // 서버 에이전트가 공식 사이트에서 검증해 채움
        "income_classes": ["기초생활수급", "차상위", "한부모"],
        "age_min": 5, "age_max": 18,       // 공식 확인 필요 → verified 플래그
        "disability": "any"                 // any|required|none
      },
      "benefit": "월 최대 N만원 강좌비 지원",  // 공식 확인 값
      "apply": { "how": "...", "url": "https://svoucher.kspo.or.kr", "docs": ["..."] },
      "sources": [{ "url": "...", "checked": "2026-07-20" }],
      "verified": true
    },
    { "id": "dvoucher", "name": "장애인스포츠강좌이용권", "...": "공식 검증 필수(연령·소득기준!)" },
    { "id": "public_program", "name": "공공체육시설 프로그램(무료/저가)", "eligibility": { "income_classes": "any", "disability": "any" } }
  ],
  "alt_edges": [           // 대체경로 — 전문가 큐레이션 규칙
    { "from": "svoucher", "when": "income_fail", "to": "public_program",
      "note": "이용권 소득기준 미달 → 공공시설 무료/저가 프로그램", "curated": "검증 대기" },
    { "from": "dvoucher", "when": "age_fail", "to": "public_program",
      "filter": { "disability_support": true }, "curated": "검증 대기" }
  ],
  "fitness_map": [         // 체력 약점 → 운동 → 종목 (시드 15~25개, 체대 검증 대기)
    { "weakness": "유연성", "exercises": ["요가", "스트레칭", "필라테스"], "sports": ["요가", "필라테스"] },
    { "weakness": "심폐지구력", "exercises": ["걷기", "수영", "자전거"], "sports": ["수영", "에어로빅"] }
  ]
}
```

체력 약점 판정: 국민체력100 항목(악력·윗몸말아올리기·앉아윗몸앞으로굽히기·왕복오래달리기 등)의
연령·성별 기준 대비 하위 여부. **정식 기준표를 못 구하면** 데모용 근사 기준을 쓰되 UI에
"데모 기준"이라 명시(날조 금지 원칙의 연장).

## 4. API 계약 — docs/API.md 참조 (요약)

- `POST /api/assess` — 입력: 나이·성별·시군구코드·소득계층(자가선언)·장애{유무,유형}·(선택)좌표
  → 출력: 제도별 자격 판정+사유, 경로(엣지 배열), 근처 자원, 공급공백, 커버리지 통계
- `POST /api/fitness` — 측정값 → 약점·운동·추천종목·동영상링크·되는 시설 필터
- `GET /api/meta/sigungu`, `GET /api/demo/personas`
- 에러 규약: `{ "error": { "code": "UPPER_SNAKE", "message": "한국어" } }`

## 5. 데모 페르소나 4 (자격 O/X × 장애 O/X)

| # | 인물 | 기대 결과 |
|---|---|---|
| P1 | 10세 여 · 기초수급 · 성북구 · 비장애 | svoucher 자격 ✓ → 신청안내 + 근처 가맹시설·자부담 계산 |
| P2 | 27세 남 · "그 외(낀 계층)" · 성북구 · 비장애 | svoucher ✗(소득) → 대체경로 → 공공시설 + 체력처방 결합 |
| P3 | 14세 여 · 차상위 · 지체장애 · 성북구 | dvoucher 자격 ✓ → 장애인 가맹시설(접근성 필터) |
| P4 | **서버 에이전트가 dvoucher 공식 자격 검증 후 확정** — 소득기준이 없다면 "72세 청각장애(연령 초과)"로, 소득기준이 있다면 "43세 시각장애(소득 미달)"로 | dvoucher ✗ → 장애 특화 대체경로 or 공급공백 신호 |

P4가 이 계약의 유일한 미정 지점이며, **공식 검증 결과가 페르소나를 결정**한다.
fixtures에는 성북구 인근 장애인 지원 시설을 0~1개만 넣어 **공급공백 배너**도 데모되게 한다.

## 6. 기술 스택 & 리포 구조

- `server/` — **Python 3.11+ FastAPI + SQLite**(fixtures→build_db) + pytest. 외부 의존 최소
  (fastapi, uvicorn, pydantic, pytest, httpx). LLM 사용 없음(전부 규칙·데이터).
- `web/` — **React 19 + Vite + TypeScript + Tailwind v4**. 지도는 **Leaflet + OSM 타일**(키 불필요).
  API 베이스 `/api` (vite dev proxy → :8000). 모바일 우선(심사위원 폰).
- `scripts/` — fetch_data.py(키 주입형), geocode.py, build_db.py.
- 배포(빌드 후 단계): Docker + 기존 오라클 서버 Caddy. MVP 단계에선 미포함.
- **[v2 2026-08-18] 챗 NLU**: OpenAI API(무료 일일 토큰 250만, 기본 `gpt-5.4-mini`) — 자유 텍스트 이해 전용,
  칩 경로는 LLM 무호출. 계약은 `ARCHITECTURE.md §11`·`API.md /api/chat/*`·`PRD FR-12·13`. **§0 판결 제약 전부 계승** —
  특히 §0-3(대체경로를 "AI 추론"이라 부르지 않음)·§0-5(자격 날조 금지)는 챗 발화에도 그대로 적용된다.

## 7. 검증 바 (통과 못 하면 미완)

- 서버: `pytest` — 자격 매트릭스(4페르소나 + 연령 경계 5·18·69), 대체경로 라우팅, 공급공백 계산.
  `uvicorn` 기동 후 4페르소나 `POST /api/assess` 계약 형태 검증.
- 웹: `tsc --noEmit` + `vite build` 통과. 페르소나 4 버튼 → 각 기대 결과 카드 렌더.
- 통합(오케스트레이터가 수행): 서버+웹 동시 기동, Playwright로 P1~P4 클릭 → 기대 문구/경로 시각화
  확인 + 스크린샷 4장.

## 8. 카피 톤

전부 한국어. 단정 대신 정확: 자격은 "판정"이 아니라 "예상 자격"(최종 확인은 공식 신청처).
모든 자격 카드 하단에 출처 링크 + 확인일. 비하 없는 중립 표현(취약계층→"지원 대상" 등 맥락 존중).
