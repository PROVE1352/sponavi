- 조건 3(판사2 전제): 이 헤드라인의 신뢰는 좌표 정직성(FR-04) 구현 위에서만 성립 — D-3 머지가 선행.

## 0. 제품 원칙 (전 기능 공통 — 위반하면 그 기능은 미완)

- **P-1 정직성**: 모르는 것은 모른다고, 근사값은 근사라고 표시한다. 거짓 정밀도 금지.
- **P-2 레인 분리**: 자격·위치·가격 = 결정론(규칙+SQL). AI는 체력처방 조언만. AI 출력이 자격·시설·가격을 언급하면 폐기.
- **P-3 비저장**: 사용자 입력(소득·장애 등)은 요청-응답 한정. 서버 로그에 바디 미기록. 저장되는 것은 익명 캐시 키(해시)뿐.
- **P-4 예상 자격**: "자격"은 항상 "예상 자격"으로 표기, 공식 신청처 링크+출처·확인일 각주 동반.
- **P-5 접근성**: 장애인이 1차 사용자다. §7 접근성 요구는 기능 요구와 동급이다.

## 2. 기능 요구사항 — 코어 플로우

### FR-01 입력 위저드 *(v1.3에서 FR-12로 대체 — AC1~4의 요구는 FR-12 AC6이 계승)*
사용자가 나이·성별·시군구·소득계층(4택 자가선언)·장애(유무+유형 8택)를 입력한다.
- AC1: 필수값 미입력 시 제출 불가 + 어떤 값이 빠졌는지 필드 옆 안내.
- AC2: 시군구는 검색 가능한 셀렉트(전국, sigungu 테이블 278개 — 서울만 아님).
- AC3: 소득계층 선택지에 "잘 모르겠어요" 포함 → 선택 시 결과에 "기초·차상위 확인 방법" 안내 블록 추가(복지로/주민센터 링크). *(오해 사각지대 대응: 자기 계층을 모르는 사용자가 다수)*
- AC4: 입력 어디에도 이름·연락처·주민번호 요구 없음(P-3).

### FR-02 자격 판정 카드
제도별 "예상 자격 ✓/✗" + 조건별 사유 + (✓시) 신청 방법·서류·기간·공식 링크.
- AC1: 사유는 조건 단위로 표시("연령 5~18세 — 27세는 범위 밖")— reasons 배열 그대로.
- AC2: 카드 하단에 출처 URL + 확인일("2026-07-20 공식 확인"). `verified:false`면 "공식 확인 필요" 배지.
- ★AC3(2026-07-21 정밀화 — 공식 선정순위 실사 반영): 장애 있음 + dvoucher 대상일 때 카드 최상단에 **"소득과 관계없이 신청할 수 있습니다"** 강조(오해 격파 훅 유지) + 바로 아래 **"선정은 우선순위제"** 블록: 사용자 입력(나이·소득계층)으로 공식 5단계 선정순위 중 **내 예상 순위를 결정론 계산**해 표시("예상 5순위(성인·비저소득) — 지자체 예산에 따라 대기 가능"). 신청 자격과 선정을 혼동시키는 표현 금지 — rules.json `selection_priority`(공식 출처·확인일 포함)만 사용.
- AC4: ✗여도 카드가 사라지지 않는다 — "왜 안 되는지"가 정보다.
- ★AC5(3심 신설 — 판사3 치명결함 봉합): 대체경로는 **매칭 엣지 전부**를 평가해 상위 3개까지 노출한다(현행 첫 매칭 1개 노출은 결함). 특히 예상 4~5순위(비저소득) 사용자는 순위 안내 바로 아래 **"지금 바로 되는 것"** 고정 블록 — 소득 무관 제도(튼튼머니 등)·세제(문화비 소득공제)·감면 안내를 `curated: 공식 확인` 엣지에서만 렌더.

### FR-03 경로 시각화
개인→제도(✓/✗)→(대안)→시설의 스텝 다이어그램.
- *(v1.4 개정 2026-08-18)* 배치: **메인 결과에서는 경로 시각화를 렌더하지 않는다**(접힘 버튼도 없음 — 사용자 확정: 실사용 화면은 카드·대안만). `/#/demo` 결과에서만 항시 펼침. §0-4 "3분 체감"(경로 시각화 필수·페르소나 원클릭)은 심사 진입로인 데모 페이지가 전담 — 판결 명령의 대상 화면이 데모 페이지로 이동한 것이며 폐기가 아님. "왜?"의 실사용 대체는 FR-02 AC1 사유(reasons)가 카드 안에서 계속 담당.
- AC1: path 배열의 엣지 라벨·결과색(✓초록/✗빨강, 색+아이콘+텍스트 삼중)이 렌더.
- AC2: `curated:"검증 대기"` 엣지에 "전문가 큐레이션" 뱃지.
- AC3: 모바일 390px에서 가로 스크롤 없이 표시(세로 접힘 허용).

### FR-04 근처 자원 (지도+리스트) — ★좌표 정직성 (2심 판사2 처방, 협상 불가)
- ★AC1: **좌표가 구 중심 폴백인 시설(voucher/dvoucher)은 마커·리스트에 "위치 근사(구 중심)" 배지**를 단다.
- ★AC2: **"반경 N km" 문구는 실좌표 보유(public) 풀에만 사용**한다. 이용권 시설은 **"성북구 가맹 N곳"**(구 단위 카운트)으로 표기한다. dist_km는 근사 시설에 표시하지 않는다.
- AC3: 마커 색: 이용권=파랑, 공공/대안=초록, 장애인=보라 (범례 상시).
- AC4: 리스트 항목: 시설명·종목·(실좌표면 거리)·수강료·**자부담 계산**(`max(0, 수강료−지원금)`, 지원금 상수는 rules.json 값)·장애인지원 태그(1/0/미상 3상태).
- AC5: 지도는 OSM 타일 + attribution. 마커 20개 초과 시 상위 20 + "더보기".

### FR-05 공급공백 배너 + 커버리지 (정직 신호, 상시)
- AC1: 해당 소스 시설 카운트 0이면 결과 최상단에 경고 배너: "이 지역엔 ○○ 시설이 없습니다 + 최근접 시설명·거리(실좌표일 때만 km, 아니면 '△△구')".
- AC2: 커버리지 존재 구: "이 구 {계층} {target}명 중 {recipient}명 수령({rate}%)" 한 줄. **없는 구는 "수급 통계 데이터 없음"** — null을 0이나 추정으로 채우지 않는다(P-1).
- AC3: 배너는 닫을 수 있으나 기본 표시.

### FR-06 데모 페르소나 바 *(v1.3에서 FR-12로 대체 — AC1~2는 FR-12 AC5가 계승)*
- AC1: P1~P4 버튼, 클릭 1회로 해당 결과 화면 완성(입력 프리필+자동 제출).
- AC2: 각 버튼에 기대 결과 한 줄(라벨) 표시.

### FR-10 접근성 정보·필터 (2026-07-21 신설 — dvoucher 웹 보조 소스 E76, P-5 직결)
장애인 사용자가 시설을 **장애지원유형·편의시설로 거를 수 있고**, 시설 카드에서 접근성 실물 정보를 본다.
- AC1: 장애 있음 입력 시 결과 리스트에 편의시설 필터 노출(장애인 화장실·엘리베이터·전용주차·단차없음·휠체어대여·수중리프트 등 11종) + 장애지원유형 필터(8종).
- AC2: 시설 카드에 장애지원유형 목록("지원: 지체, 뇌병변, 시각…")과 보유 편의시설 태그 표시. 데이터 없는 시설은 "접근성 정보 없음"(P-1 — 없는 것과 미상을 구분).
- AC3: 접근성 정보 블록에 출처 표기: "장애인스포츠강좌이용권 웹 공개 정보 기준 · 확인일 YYYY-MM-DD".
- AC4: P3(지체장애) 데모에서 편의시설 필터 1개 이상 적용된 화면 시연 가능.
- AC5: 처방→강좌 연결(FR-09)에도 동일 필터 전파 — 장애 사용자의 처방 결과 강좌는 접근 가능 시설 우선 정렬.

### FR-11 신청 가능 여부 표시 (P2 우선순위 — svoucher 웹 보조 소스 E75)
- AC1: 강좌에 신청기간 데이터가 있으면 "신청기간 MM.DD~MM.DD" + 기간 내면 "지금 신청 가능" 뱃지, 지났으면 회색 처리(숨기지 않음).
- AC2: 대면/비대면 구분 표시. 공급공백 지역(FR-05 배너)에서는 "비대면 강좌 대안" 블록 노출.
- AC3: 데이터 없는 강좌는 아무 뱃지도 달지 않는다(추정 금지, P-1).

### FR-12 챗 대화 흐름
챗 스트림이 유일한 입구다. 질문 순서·분기·봇 발화 템플릿은 클라이언트 결정론 상태기계(`web/src/chat/policy.ts`)가 소유한다.
- AC1: 모든 슬롯 질문은 **칩(버튼) + 자유 텍스트 병행 입력**. 칩 경로는 LLM 0회 호출로 판정 카드까지 완주 가능(e2e·데모의 기본 경로). *(v1.6)* 칩은 컴포저가 아니라 **해당 질문 버블 아래 스트림 인라인**으로 부착(표준 퀵리플라이 문법). 응답 후엔 선택 표시로 잠금(과거 질문 칩 재활성 금지 — 정정은 정정 칩 경로). 컴포저는 텍스트 입력+보내기만. *(v1.7)* 지역 질문의 **인라인 검색 필드는 제거** — 연령과 동일한 2단계 칩(시도 → 시군구, 시군구 1곳뿐인 시도는 즉시 확정)으로 통일. 텍스트 입력은 컴포저가 담당하며, LLM off/강등 모드에서도 클라이언트가 시군구 목록 로컬 결정론 매칭(정확 1건 확정·복수 후보 칩·0건 재질문)으로 동일 동작.
- AC2: 봇의 **사실 문장(자격·금액·시설·거리·순위)은 전부 템플릿+엔진 출력**. LLM 유래 문장은 공감·전환 멘트만 허용(FR-13 AC5 후필터로 강제) — P-2의 챗 확장.
- AC3: 판정 결과는 기존 카드 컴포넌트(FR-02~05·FR-10의 AC 전부 계승)를 채팅 스트림에 임베드. 지도·시설 목록·접근성 필터는 컨텍스트 패널에 표시하되, **패널 없이 스트림만으로 정보 완결**(A11Y-1 "지도 없이 완결" 계승). *(v1.4)* 모바일은 결과 도착 시 패널이 **상단 시트로 자동 표시**되고 위에서 아래로 슬라이드(200~300ms), `prefers-reduced-motion` 시 즉시 표시. 접기 버튼 유지.
- AC4: LLM off·호출 실패·쿼터 소진 시 같은 챗 UI에서 **칩 모드로 강등** + "규칙 기반 모드 — 버튼으로 선택해 주세요" 정직 라벨(§6 사전). 강등이 대화를 끊지 않는다(NFR-2).
- AC5 *(v1.4 개정, 2026-08-18)*: **메인 랜딩은 실사용 전용** — 데모 안내 문구·P1~P5 퀵스타트 칩을 제거하고 인사+비저장 고지 후 곧바로 첫 질문을 시작한다. P1~P5 원클릭 데모는 해시 라우트 **`/#/demo`**(데모 페이지)로 이전 — 심사·시연 진입로이며 클릭 1회 완주 요건(FR-06 AC·FR-P4·P5·게이트 8~9)은 이 페이지가 충족한다. 목모드 "데모 데이터" 배지도 데모 페이지 소관.
- AC6: 필수 슬롯 미완 시 제출 불가·부족분 재질문, 시군구는 검색 가능 선택지, 소득 "잘 모르겠어요" 선택 시 확인 방법 안내 블록, 이름·연락처·주민번호 무요구(FR-01 AC1~4 계승). *(v1.5)* 연령 입력은 2단계 칩 — 연령대(9세 이하/10대/20대/…/70대 이상) 선택 → 해당 구간 세부 나이 칩(+자유입력 병행). **예상 판정은 정확 나이로만 수행** — 구간 대표값 추정 금지(P-1·P-2, 경계 나이 5·18·65 등).
- AC7 *(v1.4 개정)*: 외부 AI 전송 고지는 **컴포저 상시 노출을 제거**하고(사용자 확정 — 화면 경량화), 대화 시작 시의 비저장 고지 버블에 한 구절로 통합한다("자유 입력 문장은 AI 이해를 위해서만 외부 AI에 전달돼요" 취지). 고지 자체의 존재는 유지(무료 티어 데이터 공유 조건 대응, P-3 연장).
- AC8: 채팅 스트림은 `role="log"` + aria-live로 신규 봇 메시지 낭독, 390px 무가로스크롤(NFR-4), A11Y-1~5 전부 유지.
- AC9 *(v1.5, v1.7 확장)*: 판정 카드·시설 카드 나열은 **가로 스와이프 카루셀**(스크롤 스냅, 자체 가로 스크롤 컨테이너 — NFR-4 허용 예외, PathDiagram과 동일 문법: 넘김 힌트·키보드 스크롤 가능·엣지 페이드). 세로 스택으로 스트림이 길어지는 것 방지. 데스크톱(lg+)은 기존 그리드 유지 가능. *(v1.7)* 모바일(<lg)에서는 판정 결과 블록 전체(판정 카드들 → 대체경로/지금 바로 되는 것 → 공급공백·커버리지 → 시설 요약)를 **하나의 가로 스와이프 결과 덱**의 슬라이드들로 통합 — 결과가 세로로 여러 버블로 쌓이지 않는다. 오토스크롤은 결과 덱 도착 시 **덱 시작점으로 1회만**(블록별 연쇄 스크롤 금지), 후속 칩 등장은 추가 강제 스크롤 없음. 스트림만으로 정보 완결(AC3)은 덱이 스트림 내부이므로 유지.
- AC10 *(v1.5, v1.6 확장)*: 봇 발화 버블은 **타이프라이터 효과**(글자 순차 표시 15~25ms/자)로 나타난다. `prefers-reduced-motion` 시 즉시 전체 표시. 스크린리더에는 완성 문장을 1회 낭독(문자 단위 aria-live 갱신 금지). 카드·고지 블록·사용자 버블에는 미적용. *(v1.6)* 연속 봇 메시지는 **동시 마운트 금지 — 순차 등장**: 앞 버블 타이핑 완료 → 타이핑 인디케이터(점 3개, 300~600ms) → 다음 버블 등장·타이핑. 초기 부팅(인사→첫 질문)도 동일. 질문의 인라인 칩은 해당 버블 타이핑 완료 후 표시. reduced-motion 시 전부 즉시.
- AC11 *(v1.5, 마이크로 모션)*: 전반적 "부드러움" — 신규 버블·카드 등장은 fade+미세 상승(150~250ms ease-out), 칩·버튼 hover/press 전이, 스트림 자동 스크롤 smooth, 카루셀 스냅. 전부 `prefers-reduced-motion` 시 비활성. 과한 모션(패럴랙스·바운스·장식 애니메이션)은 금지 — 디자인 시스템 anti-pattern 준수.

### 챗봇 페르소나 — "나비" (카피 가이드, 2026-08-18 확정 — 템플릿·LLM reply 프롬프트 공통)

- **화자**: 스포내비의 안내자 캐릭터 **나비**. 봇 메시지 발신자명 "나비" + 나비 아바타 아이콘(brand 토큰 색 SVG 권장, 이모지 🦋 허용은 아바타 한정). 첫 인사에서 1회 자기소개: "안녕하세요, 스포내비 안내자 나비예요."
- **말투**: 담백하고 따뜻한 존댓말("~예요 / ~해 주세요"). 한 버블 1~2문장. **본문 텍스트 이모지 미사용**(아바타 제외).
- **쉬운 말**: 공문서 용어는 첫 등장 시 짧게 풀이(예: 차상위 → "기초생활수급 바로 위 소득 구간"). 고령·장애 당사자 가독성 우선.
- **성격**: 재촉하지 않음. 과장 금지("좋은 소식이에요!" 남발 금지). 자격 ✗ 결과에도 담담하게 + 바로 대안 제시 — 정직성 원칙(P-1)의 톤 버전. 동정·시혜 어투 금지(§8 카피 톤 계승).
- **경계**: 나비의 멘트는 공감·안내·질문만. 자격·금액·시설·순위의 사실 진술은 나비가 아니라 **카드가 말한다**(FR-12 AC2). LLM reply 프롬프트에도 동일 지시 + FR-13 AC5 후필터가 이중 강제.

### FR-13 챗 NLU 계약 (서버 `POST /api/chat/nlu` — API.md 참조)
- AC1: 프로바이더 env `SPONAVI_CHAT_LLM`(openai|off), 모델 env `SPONAVI_OPENAI_MODEL`(기본 gpt-5.4-mini) — FR-08 AC1과 동일 문법, `ai.py` 프로바이더 패턴 미러.
- AC2: LLM 출력은 structured output + pydantic 검증. 검증 실패 → 1회 재시도 → rules 폴백(FR-08 AC2 문법).
- AC3: 응답에 `provider: openai|rules` 필드 — 클라 정직 라벨의 원천(FR-08 AC3 문법).
- AC4: **지역은 원문 문자열까지만 LLM이 추출**하고, 시군구 코드 확정은 서버가 sigungu 테이블 대조로 결정론 수행(정확 1건→확정, 복수→후보 반환·칩 재질문, 0건→미갱신). LLM이 코드를 고르지 않는다(P-2 확장).
- AC5: `reply` 후필터 — 숫자·금액·%·프로그램명·자격 단정 표현 감지 시 reply 폐기(null), 클라는 템플릿 사용(FR-08 AC6 문법, `_whitelist_filter` 미러).
- AC6: 발화 원문·슬롯을 서버 로그에 기록하지 않는다(P-3). 관측 로그는 `{provider, ms, ok, fallback_reason}`만.
- AC7: 프롬프트 인젝션 방어 — 발화가 무엇이든 판정 입력은 pydantic 검증 통과 슬롯만 반영됨을 테스트로 증명(발화로 자격·순위 조작 불가).
- AC8: FAQ 자유 질문은 intent=ask_faq + faq_key 라우팅만 — **답변 본문은 rules.json verified 필드로 조립한 고정 사전**(`GET /api/chat/faq`)에서 나온다. LLM이 답을 쓰지 않는다(§0-5 날조 금지). *(v1.8 단서, 친구 QA 반영)* 자격 사실이 아닌 **서비스 자체 설명 항목**(`how_it_works` — 데이터 출처·판정 방식·비저장 고지, 자격 수치 미포함)은 코드 소유 고정 문안으로 허용. 꼭 맞는 키가 없으면 faq_key=null(억지 유사 매칭 금지 — "조사 방식" 질문이 신청방법 카드로 오라우팅되던 실사례 봉합).
- AC9 *(v1.9 접지 답변 레인 — "AI가 적절하게 답해야" 사용자 확정, AC8 개정)*: 질문형 발화에는 LLM이 `answer`(자연어 답변)를 직접 작성한다. 단 **재료는 서버가 시스템 프롬프트에 주입한 검증 텍스트(FAQ 사전 전문 + 서비스 사실)만**. 서버 후필터(fact-lock)가 answer의 **모든 숫자 토큰과 제도명이 재료 원문에 실재하는지 대조** — 불일치 시 answer 폐기하고 AC8 카드 폴백(무응답이 오답보다 낫다). **2인칭 자격 단정("당신/고객님은 대상·자격") 상시 차단** — 판정 문장은 엔진 카드만(FR-12 AC2 불변). answer 채택 시에도 출처 동반(faq_key 카드 부착 또는 출처 줄). P-2·§0-5의 "사실 원천 = 검증 텍스트" 규칙은 이 레인에서도 동일하며, 바뀌는 것은 원천이 아니라 **표현 주체**뿐이다.

## 3. 기능 요구사항 — AI 체력처방 (M1)

> 2026-07-21 실사(E79~E82)로 상향: 판정은 공식 컷오프(문체부 고시 체계), 추천은 지식그래프 — 설계 `ARCHITECTURE §6`+`FITNESS_GRAPH.md`.

### FR-07 측정 입력 폼 (동적)
- AC1: `measurement_item` 카탈로그에서 **사용자 연령군 해당 항목만** 렌더 — 공식 5개 연령군(유아 4-6·유소년 11-12·청소년 13-18·성인 19-64·어르신 65+), 9개 체력요인 그룹핑. **대체항목(택1) 쌍은 한 슬롯으로 렌더**(예: 심폐 = 20m왕복 또는 스텝검사 중 하나 — 공식 기준표의 A/B 구조).
- AC2: 전 항목 선택 입력(null 허용) — 최소 1개 입력 시 제출 가능.
- AC3: 각 항목에 단위·측정법 힌트(예: "악력(kg) — 양손 중 높은 값").
- AC4: "국민체력100 인증센터에서 무료 측정 가능" 안내 + 센터 찾기 링크.
- ★AC5(스크리닝, 제도 준용): 폼 앞단에 문진 게이트 — "심장질환·흉통 등 PAR-Q 항목 해당 시, 또는 혈압 160/100 이상이면 측정·고강도 운동 전 전문가 상담" 고지. 응답은 저장하지 않는다(P-3).
- AC6(연령 공백 정직): 만 7~10세 입력 시 "이 연령은 국민체력100 공식 기준이 없습니다" 고지 + 유소년 참고 콘텐츠로 안내(P-1 — 공백을 숨기지 않음).
- AC7(비인증 표기): 결과 등급은 항상 **"참고 등급(추정)"** 라벨 — "공식 인증은 체력인증센터(무료)에서만" 문구 동반(제도상 자가측정=비인증).

### FR-08 AI 처방 호출
- AC1: 프로바이더 순서 = env `SPONAVI_LLM`(claude|gemini|off). off 또는 실패 시 룰 폴백.
- AC2: LLM 출력은 pydantic 스키마 검증(약점[]·우선순위[]·처방[{운동,요인,강도,빈도}]·주의). 검증 실패 → 1회 재시도 → 폴백.
- AC3: **응답에 `provider: claude|gemini|rules` 필드** — UI가 "AI 보조 처방" vs "기본 규칙 처방" 구분 표기(P-1).
- AC4: 캐시: (연령군·성별·항목값 반올림) 해시 **+ norm_version + graph_version** 적중 시 재호출 없음 — 기준표·그래프 갱신이 캐시를 자동 무효화.
- AC5: 처방 화면에 고지 문구 고정: "운동 참고 정보이며 의료 조언이 아닙니다. 통증·질환 시 전문가와 상담하세요."
- AC6: LLM 프롬프트에 시설·가격·자격 언급 금지 지시 포함, 응답에 해당 내용이 있어도 서버가 무시(P-2).
- ★AC7(근거 접지): 약점 판정은 **공식 컷오프(fitness_norm, 출처=문체부 고시 체계)와의 비교문**으로 표기("교차윗몸 38회 — 19~24세 남 3등급 컷 42회 미달"). LLM이 판정하지 않는다(P-2 확장).
- AC8(왜? 펼침): 각 처방 항목에 "왜 이 운동?" 펼침 = 그래프 근거 경로+출처 배지(공단 공식 기준/처방 실적 N건/정부 지침/전문가 큐레이션·검증 중) — 자격 카드의 사유(FR-02)와 동일 UX 문법.
  - *서버 측 상태(2026-08-22)*: `/api/fitness/ai` 응답 `처방[].provenance`(source·tier·weight·curated_status·via_goal) 제공 완료 — 값은 서버가 그래프에서 채우고 LLM 값은 덮어쓴다. **UI 펼침 렌더는 미구현**(웹 배치 잔여).

### FR-09 처방→강좌 연결 (결정론 복귀)
- AC1: 처방 운동명 → 종목 사전 정규화 → 사용자 시군구의 시설·강좌 필터("이 운동 되는 근처 강좌 N곳").
- AC2: 매칭 0곳이면 숨기지 말고 "이 운동을 다루는 등록 강좌가 이 지역에 없습니다" + 공공시설 일반 대안(P-1).
- AC3: 국민체력100 공식 동영상 링크 최소 1개(약점 요인·연령군 매칭 — 운동처방가이드 8,303건 등 영상 API 7종, E81).
- ★AC4(공급 인지 처방): 추천 랭킹에 근처 강좌 가용성 반영 — 1순위 운동이 지역에 0곳이면 **차선 운동을 근거와 함께 제시**("수영이 최적이나 반경 내 강좌 없음 → 대안: 에어로빅(심폐지구력, 근처 3곳)"). 1순위를 숨기지 않고 함께 표기(P-1).
- AC5: 장애 사용자는 FR-10 접근성 필터가 강좌 연결에 전파(접근 가능 시설 우선).

## 5. 데이터 요구사항

- DR-1: DB 갱신 월 1회(`bulk_fetch + scrape_* → build_db → build_graph`), 갱신일을 UI 푸터에 표기("데이터 기준 2026-07-20").
- DR-2: 자격 수치(연령·지원금)는 rules.json에서만 — 하드코딩 금지. 출처 URL·checked 필수.
- DR-3: coverage 확장(전국)은 문화빅데이터 CSV 확보 시 동일 스키마로 적재. 그 전까지 15구 외 null.
- DR-4(웹 보조 소스): sv/dv 웹 파싱 필드(접근성·신청기간·대면비대면)는 **전부 NULL 허용 애드온** — 스크레이핑 실패 시에도 API-only로 전 기능 동작. 적재 전 웹↔API 조인 표본 대사(불일치율 임계 초과 시 미적재). 제출물·UI에 "공단 웹서비스 공개 조회(보조)" 출처 표기.
- DR-5(공식 컷오프): fitness_norm은 nfa 인증기준표 스크레이핑만이 원천 — 수기 입력·추정 보간 금지. 부등호·범위 문자열 셀은 원문 그대로 보존(cut_rule). 각 행에 source·checked. 등급 판정 문구에는 항상 기준 출처 각주.
- DR-6(백분위 보조): 측정결과 API 기반 "상위 N%" 표시는 데이터 시점(2011~2019) 명기 — 최신성 오인 금지.
